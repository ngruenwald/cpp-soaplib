# SOAP 1.2 Specification Compliance

This document tracks the gaps between the current `cpp-soaplib` implementation and the [W3C SOAP 1.2 Specification](https://www.w3.org/TR/soap12/).

## Identified Gaps

1.  **Fault Handling**: No support for structured SOAP Faults. The library uses raw string exceptions and HTTP 500 with plain text.
2.  **Processing Model**: Missing `mustUnderstand` attribute validation. Receiver must fail if a mandatory header is not understood.
3.  **Header Attributes**: No support for `role` (replaces `actor`) and `relay` attributes.
4.  **Binding**: Limited HTTP binding (POST only). Specification requires supporting "SOAP Web Method Feature" (GET).
5.  **MEPs**: Only basic Request-Response implemented. Spec defines several Message Exchange Patterns.
6.  **Encoding**: Section 5 data encoding (complex graphs/arrays) is not supported.

## Roadmap & Tasks

### Priority 1: Fault Handling (Basic)
- [x] Define `SoapFault` data structure in `soaplib` (Code, Reason, Node, Role, Detail).
- [x] Implement `SoapFault` serialization to XML.
- [x] Update `SoapServer::HandleRequest` to catch `std::exception` and return a structured `SoapFault` envelope.
- [x] Implement `SoapFault` deserialization from XML.
- [x] Update `SoapTransport` to detect SOAP Faults in responses (even if HTTP status is 500).
- [x] Introduce `SoapFaultException` that carries the structured fault data.

### Priority 2: Processing Model & Headers
- [ ] Implement `mustUnderstand` attribute parsing in XML headers.
- [ ] Add a "Known Headers" registry to `SoapBase` or `SoapServer`.
- [ ] Implement validation logic in the dispatcher: fail if `mustUnderstand="1"` and header is unknown.
- [ ] Add support for the `role` attribute when creating/parsing headers.
- [ ] Add support for the `relay` attribute when creating/parsing headers.

### Priority 3: Binding & Transport
- [ ] Update `HttpSoapTransport` to handle HTTP 202 (Accepted) for one-way messages.
- [ ] Implement support for HTTP `GET` in `HttpSoapTransport` (Web Method Feature).
- [ ] Ensure `Content-Type` is strictly compliant with `application/soap+xml`.
- [ ] Support HTTP 400/500 status codes correctly as potentially containing valid SOAP Faults.

### Priority 4: Advanced Spec Features
- [ ] Support for hierarchical SOAP 1.2 Subcodes in Faults.
- [ ] Implement "Response-Only" MEP support.
- [ ] Implement "SOAP Action" parameter in `Content-Type` header (replaces `SOAPAction` header in 1.1).
- [ ] Investigate basic support for Section 5 Encoding (RPC/Encoded).
